# Workflow

**Onboard mode** (prompt says `mode: onboard`): skip these steps. Follow [onboard.md](../../../skills/muffy/references/onboard.md) 0c: read `docs/architecture/baseline.md`, write `docs/adr/NNNN-existing-stack.md` (numbered after the latest; link existing ADRs instead of duplicating them), `docs/design-system/README.md` only when the prompt says the repo has a UI, and, only when the repo has no architecture diagram at all ([diagrams.md](diagrams.md), "Onboard overview"), a `diagrams_spec` entry for a high-level `docs/architecture/overview.html` — `designer` draws it at 0c', not you. Record what exists; recommend nothing. No `contract.md`.

**Lite profile** (prompt says `Profile: lite`): there is no `brief.md` and no `design.md`; `ac.md` was written by the Orchestrator and names `Kind:` and `Owner:`. Write the contract as in normal mode below, for the owners named only. If the work needs something this lane skips, do not design around it: hand off `status: blocked` with one blocker whose `owner` says who is missing (`Researcher` for a new dependency, provider or stack fact; `PM` for a change users or outside callers see, or auth, permissions or personal data; `Designer` for a screen, flow or component) and whose `problem` names the AC. The Orchestrator promotes the task to the full flow ([lite-profile.md](../../../skills/muffy/references/lite-profile.md#promote-to-the-full-flow)).

**Normal mode:** if the prompt gives a `baseline.md` path, read it before step 1 and reuse its Stack and Conventions in step 6.

1. Read the existing code structure; reuse existing patterns
2. Write the contract as an index plus one part file per section (see [output-format.md](output-format.md)); `contract.md` holds only a one-line summary and a link per section. Make the contract complete enough for FE/BE to work separately: endpoint, method, request/response schema, error codes, status codes
3. Define schema / migrations that need to change
3b. **Diagrams, only if a trigger fires.** Check the triggers in [diagrams.md](diagrams.md) against the contract you just wrote; none fires → no diagram, note `diagrams: none needed (<reason>)`. A fired trigger becomes a `diagrams_spec` entry in your hand-off, not a file — `designer` draws it. Not in the fix lane (onboard mode: only the one-time overview above)
4. Specify **file ownership** — which files FE/BE/devops edit (infra files per `deploy.md` belong to devops; runtime + version in Stack must match what `deploy.md` pins) to reduce merge conflicts; shared files get a single named owner
5. Map every AC to some part of the contract (table `AC id → endpoint/logic`) — especially security and rate limits
6. Choose **a tech stack that won't need changing after MVP** (a stack that has no practices file and no `docs/stacks/` note → return `blocked`, blocker `owner: Researcher`, problem `stack-unknown: <framework> <version>` before the contract is final, per `.claude/skills/muffy/references/stack-learning.md`):
   - Existing codebase? Reuse patterns (context defaults)
   - New codebase + confident? Document choice in contract.md + reasons
   - New codebase + unsure? Consult [`stack-defaults.md`](stack-defaults.md) — use gating defaults (Next.js + Postgres) or ranked catalog by language
   - Write choice in `contract.md` under a Stack section with reasons
   - **Build vs buy**: for each non-trivial capability (auth, payments, email, search, queue) record `build | buy | reuse` with one reason; prefer reuse of what the codebase or an existing ADR already has. A capability worth buying: read [third-party-providers.md](third-party-providers.md), propose 2 or 3 provider options, and let the user choose through the Orchestrator
   - **Cost is a delta against `docs/strategy.md`, not a fresh estimate.** `contract.md` always has a `## Cost` heading. Feature adds no new service, dependency, paid API or recurring cost → one line, `Budget: none. No new recurring cost`. Otherwise write the full section: monthly run cost (infra, third-party/API/token, licenses) and one-off effort (S/M/L per phase from `docs/plan/<task>.md`). Each figure is a range with its basis; no source for a number → mark `[assumed]`. Compare with the budget ceiling in `docs/strategy.md` (or `requirements.md`); over it, or none given and the estimate is material → say so in the final message and offer a cheaper option. **Start the `## Cost` summary line in `contract.md` with a verdict the Orchestrator reads**: `Budget: none` (no new recurring cost), `Budget: within` (figure vs ceiling), `Budget: over` (figure vs ceiling, plus the cheaper option and its figure, on that same first line), `Budget: unknown` (no ceiling and the estimate is material; name the cheaper option and its figure on that same first line), or `Budget: unlimited` (the ceiling in `docs/strategy.md` is `unlimited`: still write the figure and its basis, compared with the baseline, but there is nothing to exceed; do not offer a cheaper option unless one is clearly equivalent). A budget stop is the Orchestrator's job (`pause:budget`); you only report it Do not write `docs/strategy.md`: every build/buy choice and new recurring cost is reported in `contract/stack.md` and `contract/cost.md`, and the product-manager records them. The infrastructure part of the figure comes from `deploy.md` `## Infra cost` (devops writes it); use it, do not re-estimate it. Devops writes it in the same parallel message, so if it is not there yet write `infrastructure pending (deploy.md)` on the cost line; the alignment pass after step 3 fills the figure and settles the verdict before the Orchestrator reads it. When `deploy.md` says `infra: later`, `not-needed` or reuses existing infrastructure with no change, write `infrastructure excluded (<why>)` on the cost line instead of inventing a figure
6b. **Options before a hard-to-reverse choice.** For the stack, a datastore, the auth model, the deploy model or a module split that FE and BE will build on, write 2–3 real options in `contract/stack.md` (one line each: what it is, the trade-off, the cost delta, what it locks in) and the one you pick with the reason. One obvious option (the codebase or an ADR already decides it) → say so in one line instead
7. Write hard-to-reverse technical decisions (stack, DB, auth, deploy model, a build-vs-buy choice with a recurring cost) as an ADR at `docs/adr/NNNN-<kebab-title>.md`, numbered after the latest file, using the same format as the PM's ADRs with `Kind: technical`. Product decisions (scope, priorities, the budget ceiling) are the PM's ADRs, not yours; see [adr.md](../../../skills/muffy/references/adr.md)
8. Record in `<brain>/agents/architect/<task>.md`: date, what was done, chosen stack, decisions + reasons, files created/edited (reference paths, don't copy content), cost/token usage, open issues. For fix rounds, append as a new section
