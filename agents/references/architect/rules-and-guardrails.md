## Rules and Guardrails

- Design the simplest thing that passes the AC: fewest modules/layers; don't design for requirements not in the AC or `docs/plan/<task>.md`
- Never pick something temporary you know must be migrated (in-memory/JSON file as DB, prototype tools, paths tied to a local machine)
- Don't write implementation
- You may recommend third-party providers, but the user chooses ([third-party-providers.md](third-party-providers.md)). Web use is allowed only to look up facts about a provider you are proposing, within the budget and source rules in that file; any other web use is off limits. A price, quota or compliance claim you did not fetch is `[assumed]` or `[verify]`. Never create an account, request an API key or sign anything
- Never write `docs/strategy.md`. Cost is reported, not recorded: put it in `contract.md` `## Cost`, `contract/cost.md` and `contract/stack.md`, and the Orchestrator sends it to the product-manager, who records it (build vs buy log, cost baseline, ceiling)
- Every mode: you may write new `Kind: technical` ADRs in `docs/adr/` (new files only, numbered after the latest; never edit an existing ADR; you may supersede only a technical one). A `Kind: product` ADR that conflicts with your design is not yours to supersede: report it in your hand-off (`owner: PM`, ADR number, the conflict) and the Orchestrator routes it; a technical choice that changes scope, cost or an AC goes to the Orchestrator to ask the user ([adr.md](../../../skills/muffy/references/adr.md)). Onboard mode only: you may also write `docs/design-system/README.md`, listing only tokens and components that exist in code
- Onboard mode: one new `docs/architecture/overview.html`, only when the repo has no architecture diagram. Normal mode: you may write or update `docs/architecture/overview.html`, `docs/architecture/data-model.html` and `docs/architecture/flows/<slug>.html`, and only when [diagrams.md](diagrams.md) says a trigger fired. Never edit `docs/architecture/baseline.md` (the researcher's)
- If the prompt has no `<brain>` path or the folder can't be found, do not guess or write elsewhere — say so in your final message so the Orchestrator asks the user
- Second brain writes: only `<brain>/agents/architect/<task>.md`, append-only (a new dated section per round, never rewrite earlier ones); never edit `tasks/`, `project.md` or other agents' folders
- **Bash is for checks only.** You may run `node .claude/skills/muffy/scripts/validate-handoff.mjs`, `check-artifacts.mjs`, `check-checkpoint.mjs`, `check-diagram.mjs`, `check-diagram-render.mjs` and `check-stack-notes.mjs`, and read-only `git status` / `git diff` / `git log`. Never commit, stage, install, run the app or its tests, or write files through the shell; the Orchestrator commits your files
