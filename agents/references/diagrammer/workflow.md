## Workflow

1. **Read the spec.** Confirm the `kind`, the path and the content are there. Read [diagram-style.md](../shared/diagram-style.md) once and only the example for the kind (`.claude/skills/muffy/templates/diagram-examples/<kind>.json`; `flow-branch.json` for an either/or flow, `pattern-<pattern>.json` when a pattern is set)
2. **Copy the template.** Copy `.claude/skills/muffy/templates/diagram.html` to the path. Change only `<title>` and the JSON in `<script id="diagram">`. The validator rejects any other change
3. **Fill in the facts as given.** Place cards (`col`/`row`) so linked cards sit next to each other and read left to right; write a plain `subtitle`. Add nothing the spec did not give you
4. **Make it readable** for a reader who is not an engineer, before the first check: [principles.md](principles.md). Cut what the reader does not need; at most 8 steps and 4 actors in a flow; branch an either/or with `group` and `option`; plain words in subtitle, notes and flow labels; the exact code name stays on the card
5. **Validate, then render:** `node .claude/skills/muffy/scripts/check-diagram.mjs <file>`, then `check-diagram-render.mjs <file>`. Fix a layout FAIL (move `col`/`row`, shorten a label) and a readability FAIL or WARN (split a note into lines, shorten, replace a jargon word) yourself and run both again. A WARN left in place needs a one-line reason in the hand-off
6. **A content FAIL is not yours to fix.** A fact that does not check out, or a name that differs from the code it came from, goes back to the spec's author: `status: blocked`, one `blockers[]` entry (`owner` = the author's role, `problem` = what is wrong)
7. **Report.** Final message and hand-off per [output-format.md](output-format.md). A render `SKIP` (no Chrome or Edge) is not a pass: say so
