# Steps

Row order is execution order: 0 → 1 → 2 → 3 → 3b → 3e → 3c → 3d → 4 → 5 → 6 → 7 → 8 → 9 → 10 → 11 → 12. Step 3a (the cost record) is not a row of its own: it runs inside row 3 and is specified in [budget.md](budget.md#recording-cost-step-3a).

Routing: an agent's `references/<agent>/when-to-use.md` (under `.claude/agents/`) lists when it is and is not the right agent. Read it only when a request or a hand-off leaves the owner unclear; the table below is the default.

| # | Agent | Input | Output |
|---|---|---|---|
| 0 | `researcher` → `architect`, once per repo | `scan.json` | `docs/architecture/baseline.md`, `docs/adr/NNNN-existing-stack.md`; Human gate `pause:onboard-review`. Existing codebases only: [onboard.md](onboard.md) |
| 1 | `researcher` | request (+ min level) | `needs-input` → interview the user first ([requirements.md](requirements.md)); then `brief.md` + level reached; `[verify]` left on a hard-to-reverse decision → send back for the next level; spikes → devops in 3d (stack spikes only; route spikes run after the first BE round, see [run-profile.md](run-profile.md)) |
| 2 | `product-manager` | `brief.md`, `requirements.md` | `needs-input` → interview the user first ([requirements.md](requirements.md)); then `ac.md`, `docs/plan/<task>.md` (phases + P0/P1/P2), `docs/adr/NNNN-*.md` |
| 3 | `designer` ∥ `architect` ∥ `devops` mode 1 — one message | `ac.md`, `brief.md`, plan | `design.md`, `contract.md`, `deploy.md` (architect may return `needs-input` to have you pick a third-party provider, designer, only when the sources conflict on the Platform, and devops mode 1, only when `infra: propose`, to have you pick the infrastructure (cloud, on-premises, hybrid): interview the user per [requirements.md](requirements.md), then resume it). A designer that created the design system returns `done` on the starter style with one non-blocking style question: keep it for the 3c question ([requirements.md](requirements.md)). When every needs-input is answered, architect aligns the contract with `deploy.md`: pinned runtime, devops-owned files, the `## Infra cost` figure in `## Cost` (the verdict is final only after this) and, when the user picked infrastructure, its ADR; record that choice as `infra: existing: <chosen>` in checkpoint `## Status` and `project.md` so it is not proposed again. Then read the `Budget:` verdict: `over` or `unknown` → `pause:budget` ([budget.md](budget.md)); then step 3a: the product-manager records the cost ([budget.md](budget.md#recording-cost-step-3a)). If the architect's hand-off carries `diagrams_spec`, relay each entry to the same `designer` (`SendMessage`, after its own canvas/screen-map work) to draw — `designer` never specs a diagram's content itself except the screen map |
| 3b | Orchestrator | `.team/<task>/canvas/` | Publish the canvas on Claude Design (Artifact type "Design", `quickstart` intent `design`), put the URL in `design.md`, and **save it right away** in `checkpoint.md` `## Status` (`canvas: <url>`) and as a link in `<brain>/tasks/<task>.md`, so a resume finds it; after `contract.md`, designer aligns fields and you republish. When `design.md` starts with `Design system: after contract`, skip the first publish (wireframes only): the align round creates the design system from the contract's Stack and applies it, then you publish once |

Validate with `check-diagram.mjs` then `check-diagram-render.mjs`, publish each file as its own Artifact (republish keeps the URL from `project.md` → `## Diagrams`), then **record it right away** in `<brain>/tasks/<task>.md` → `## Diagrams`, `project.md` → `## Diagrams` and `checkpoint.md` `## Status` (`diagrams: <n> published`). Never block: invalid or unpublishable → record why and continue. Details: [diagram-publish.md](diagram-publish.md) |
| 3c | **Design gate** (automated check, then **Human gate** `pause:design-review`) | `design.md` + URL, `contract.md` | (1) Designer's Definition of done all checked (published, every AC has an artboard, no placeholders, values from `docs/design-system/` tokens, new components documented) — else send back, no question to the user yet. (1b) **UX/UI review** of the rendered canvas by the Orchestrator ([design-review.md](design-review.md)): `high` findings go back to `designer` before the user is asked; the rest go into the question. (2) Then `AskUserQuestion` with the canvas URL, an artboard-per-AC list, new components, open `[verify]` items and the UX/UI review's remaining findings (or "review skipped: impeccable not installed"). Before asking: save `paused at pause:design-review` in checkpoint `## Status` and the vault task note. Approve / Request changes / Reject. Request changes → reasons to `designer` (+ `architect` if the contract is affected), republish, check (1) and (1b) again, ask again. **Blocks step 4 until the user approves** |
| 3d | `devops` mode 2 on `ops/<task>` (cut here from the planning commit on `feature/<task>`, setup step 7), **only if a smoke trigger is true** ([run-profile.md](run-profile.md)) | `deploy.md`, `contract.md` | `node -v` vs `.nvmrc` first (mismatch = fail), then Pass / Fail with real dependencies in one process, no feature routes needed. **Blocks step 4**; on pass, Orchestrator creates `fe/<task>` and `be/<task>` worktrees from `ops/<task>` (see setup step 7) |
| 4a | `frontend-dev` / `backend-dev`, **fix lane only** ([fix-profile.md](fix-profile.md)) | `fix.md` | `diagnosis` in the hand-off (`known` / `unknown` / `needs-full-flow`), `## Cause` and `## Repro` in `fix.md`; no code. **Blocks step 4** in the fix lane |
| 4 | `frontend-dev` ∥ `backend-dev` | `design.md`, `contract.md`, `ac.md`, branch + worktree (created after 3d) | branch + summary |
| 5 | Orchestrator | — | First `node .claude/skills/muffy/scripts/check-ownership.mjs .team/<task>` in the feature worktree: an `out-of-lane` file or one changed on `both` fe and be goes back to its owner per `contract/ownership.md` before any merge (the other side sends its need as a blocker); `unowned` notes go to the architect for a row; a `stale-contract` (a step-4 hand-off whose `contract_commit` is older than the last contract commit on `feature/<task>`) goes back to that dev to re-read the contract. Then merge into `feature/<task>` with `git merge --no-ff` (never `--ff-only`: branches diverge by design); a conflict left after that → file owner rebases |
| 5b | Orchestrator, **only if the user asked for PR diagrams (off by default; put "draw the PR diagram" in the FE/BE prompts)** | `fe/<task>` + `be/<task>` worktrees: each `.pr-lens/<title>/` render folder (folder path in the hand-off `paths_written`) | (1) Publish the PR diagrams as one Claude Artifact (not the prlens.dev canvas): `node .claude/skills/muffy/scripts/build-diagram-page.mjs <scratchpad>/pr-diagrams.html <fe render dir> <be render dir>`, then publish that file with the Artifact tool (icon `diagram`); keep the URL for `review-<n>.md`, the Human gate and the closing report.
