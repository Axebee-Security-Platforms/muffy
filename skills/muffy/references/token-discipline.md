# Token discipline

- **Prompt template** — every subagent prompt is only this, no pasted file contents (parsed shape: [prompt-envelope.schema.json](../schemas/prompt-envelope.schema.json)). Team-folder paths in `Read:` and `Write:` go under the feature worktree (`.worktrees/feature-<task>/.team/<task>/…`), never bare `.team/<task>/…`, which resolves in the main checkout:
  ```
  Goal: <one line>
  Done when: <one observable result that ends this step, e.g. "handoff validates and every AC-n in ac.md is listed">
  Task: <task>  Brain: <brain>  [Vault: <vault> — researcher only]  [Mode: 1 | 2 | 3 — devops; onboard | stack-note — researcher; onboard — architect]  [Profile: fix — fix lane only; Read: fix.md replaces ac/contract/brief/design | lite — lite lane; Read: ac.md + contract.md, no brief/design]
  [Worktree: <path> · Branch: <branch> — frontend-dev, backend-dev, qa-tester, devops mode 2; created by the Orchestrator (setup.md step 7)]
  Read: <paths>
  Write: <paths>
  Don't touch: <paths/scope>
  [Announcement: yes — docs-writer only, when the user opted in at pause:scope]
  [PR diagram: yes — frontend-dev/backend-dev only, when the user asked for step 5b ("draw the PR diagram")]
  [Human approved: <date> — devops step 11 only, after the step-10 Human gate]
  [Test level: L0–L4 — qa-tester only; copy the row from test-levels.md]
  [Full regression: approved — qa-tester only, after pause:full-regression; absent means qa-tester must run scoped tests only]
  [Checkpoint: .team/<task>/checkpoint.md — from round 2 on; read only ## Goal and ## Open blockers]
  Commit trailer: <verbatim attribution line the harness gave the Orchestrator for this session — never typed from the skill, never a model name taken from a file — passed to every agent; every commit ends with it>
  Final message: ≤ 8 lines and ≤ 1,200 characters (code-reviewer exempt: its message is saved as review-<n>.md, ≤ 120 lines) — verdict/status, paths written, blockers (ids `B-n`, from round 1 on). Details belong in files. End with the one-line JSON hand-off block; do not Read handoff.schema.json, the shape is in the next line
  Hand-off shape: <the one-line example below, with this spawn's role, task, step and round>
  ```
- **Build the prompt with the script**: `node .claude/skills/muffy/scripts/make-envelope.mjs --role <role> --step <step> --round <n> --task <task> --brain <brain> --goal "…" --done-when "…" --read a.md,b.md --write <paths> --dont-touch <paths> [--worktree … --branch …] --trailer "<attribution line>"` prints the template above, fills in the hand-off path and the hand-off shape, and validates the envelope against the schema first. Typing the template by hand costs ~1 KB of your output per spawn and drifts; use the flags (`--mode`, `--profile`, `--test-level`, `--checkpoint`, `--announcement`, `--pr-diagram`, `--full-regression`, `--human-approved` cover the optional lines)
- **Final report is capped, and the cap is enforced by you**: measured on 224 real hand-backs, the average was 4.4 KB against a 10-line rule. Every hand-back enters your context for the rest of the session. Over the cap (more than 8 lines or 1,200 characters before the JSON), do not act on the prose: route on the JSON, and on the next spawn of that role repeat the cap in `Final message:`. A report is never copied into another prompt
- **Bash output stays out of the conversation**: a command whose output may pass ~20 lines (tests, builds, `git log`/`git diff`, installs, validators on a whole folder) runs through `node .claude/skills/muffy/scripts/run-quiet.mjs [--tail N] -- <command>`. It writes the full output to a log file and prints only `exit=<code> lines=<n> log=<path>`, the last lines and the error-looking lines. Open the log with a narrow `Grep` or a `Read` with `offset`/`limit` only when that is not enough. Prefer one command that does several things over several commands that each print. Scripts in `scripts/` already print a verdict line, not a report
- **Writing JSON on Windows**: never write a hand-off or escalation file through a heredoc, `printf` or `echo` — backslashes in Windows paths break twice that way. Use the Write tool, or `JSON.stringify` in node, and then run the validator right away
- **Hand-off example** — put this in every prompt's `Final message:` line so the agent copies a valid shape (values are the allowed ones; `status` is never `ready`, `step` is a string, `blockers` is an array, `owner` is never `Orchestrator`):
  ```json
  {"role":"backend-dev","task":"<task>","step":"4","round":1,"status":"done","paths_written":["src/a.ts"],"ac_ids_done":["AC-1"],"blockers":[],"quality_checks":{"passed":true,"failed":[]},"summary":"one line"}
  ```
  A blocker looks like `{"id":"B-1","problem":"...","file":"src/a.ts:12","owner":"BE"}` with `owner` one of FE, BE, Docs, Devops, Architect, Designer, PM, Researcher
- **Agents with `Write` save their own hand-off**: put `.team/<task>/handoff/<step>-<role>-r<round>.json` in the `Write:` line of every agent except `code-reviewer`; the agent writes and validates it (its own guardrails say how). You then only validate it, or, for `code-reviewer` (read-only, no Bash), save the block from its message. Agents with check-only Bash (`architect`, `designer`, `product-manager`, `docs-writer`, `researcher`) never commit: you commit their files
- **Hand-off block**: every agent ends with one line of JSON. It is saved as `.team/<task>/handoff/<step>-<role>-r<round>.json` (by the agent, see above) and `node .claude/skills/muffy/scripts/validate-handoff.mjs <file>` runs before you act on it. Route on the JSON (`status`, `verdict`, `blockers[].owner`), not by re-reading prose. Invalid → fallback ladder in [loops.md](loops.md)
- **Lazy loading**: read a reference only at the step that needs it — `SKILL.md` links each one to its step; `closing.md` only at step 12; `hooks-enforcement.md` only at setup; `loops.md` only when a reject/fail happens; this file and `memory-model.md` once at setup. Agents follow the "Load on demand" table in their own definition; don't ask an agent to "read all references"
- **Fix rounds continue the same agent** with `SendMessage` (its context is still loaded) and send only that owner's blockers/bugs as a list. Spawn fresh only if the agent is gone
- **Incremental diffs**: export each round as `diff-<n>.patch` containing only the changes since the last review
- **Topic-split review diffs**: when `diff-<n>.patch` is over ~1,500 lines or touches more than ~15 files, run `node .claude/skills/muffy/scripts/split-diff.mjs .team/<task>/diff-<n>.patch` (it checks the size itself and does nothing when the diff is small). It writes one patch per topic, `diff-<n>-<topic>.patch`, plus `diff-<n>-index.md`; give `code-reviewer` the topic files in `Read:` instead of the whole `diff-<n>.patch`. A topic is one reviewable concern: a vertical slice (data/migration, API routes + their DB layer, client queries/hooks, UI components, infra/docs/smoke). The script keeps each test with the code it tests, splits by directory depth until a topic fits, and verifies that every file lands in exactly one topic with no bytes lost. Override its grouping with `--rules rules.json` (`[{"topic", "match": regex}]`) when the path layout hides the real concern. Limits: `--max-lines`, `--max-files`. Example, `manual-asset-mapping` (67 files, 8,164 lines) → 10 topics such as `db-migration`, `nms-ingest-routes`, `nms-ingest-db`, `nms-dashboard-shared`, `infra-docs-smoke`. Keep the full `diff-<n>.patch` for docs-writer; fix rounds are small and stay one file
- **Do not Read `handoff.schema.json`** (9 KB, was read by 31 agents in a sample of 150): the shape is in the prompt's `Hand-off shape:` line and `validate-handoff.mjs` prints exactly what to fix. Read the schema only when a validation error does not say enough
- **Turn budget**: an agent that has made about 80 tool calls without finishing stops, writes what it has, commits, and hands off `status: not-ready` with a blocker `B-n` saying what is left; the Orchestrator answers with a fresh spawn that points at `checkpoint.md`. In the sample, `designer` ran 163 turns and `backend-dev` 138 on average, and context grows with every turn, so one long run cost more than two short ones. `docs-writer` and `qa-tester` are expected to finish in under 60
- **Compact at gates**: after step 3 (planning files committed), after step 8 (review loop closed) and right before the Human gate, write `checkpoint.md` and run `/compact` with the focus line `keep: task, step, open blockers, next:`. After a compact, read only `checkpoint.md`. Do not re-invoke `/muffy` to "reload" the skill: once `SKILL.md` is in the session, follow it from where you are (the sample re-loaded it 44 times, 7 KB each)
- **Big shared docs are read by section**: `docs/architecture/baseline.md` (and its `baseline/` folder, see [onboard.md](onboard.md#baselinemd)), `docs/design-system/README.md`, `contract.md` and large source files (`Grep -n` for the heading or symbol, then `Read` with `offset`/`limit`). Put the section names in `Read:` (`baseline.md#conventions`) instead of the whole file when you know which one the agent needs. Re-reading a file already read in the same run is a defect unless it changed
- **Read narrowly**: for gates and traceability checks, grep or read only the section needed (e.g. the `AC id →` table) instead of whole files; don't re-read a file you already checked unless it changed
- **Don't relay**: never copy one agent's output into another's prompt — give the path
- **Checkpoint instead of history**: from round 2 on, point to `checkpoint.md`; don't replay earlier rounds ([memory-model.md](memory-model.md#checkpoint))
- **Follow a link, don't load the folder**: an agent opens `rounds/<step>-r<n>.md` only when its own prompt names that label or path. Never Read or Glob all of `rounds/`
- **Model tiers**: only `haiku` and `sonnet` are allowed — never pass `opus` or `fable`. Agent frontmatter sets the default (`docs-writer` = haiku, the rest = sonnet). When spawning fresh (not `SendMessage`), pass `model: "haiku"` for:
  - `qa-tester` re-running existing tests only (no new tests to write)
  - `frontend-dev` / `backend-dev` fix rounds where every bug names a file + line and the expected fix
  - `researcher` when the run profile asks for codebase-only / minimal research
  - `frontend-dev` / `backend-dev` step 4a (fix lane) when the symptom already names the file and line; see [fix-profile.md](fix-profile.md)
- **`docs-writer` stays on sonnet when the docs restate numbers or a policy list** (refused classes, limits, AC counts, test numbers): the haiku default is for prose; a list that must match the code or an AC needs the stronger model, and a repo-wide grep for the same claim
- **Learn from this project's spawn history**: before passing `model: "haiku"` for a case above, check `<brain>/project.md` `## Lessons` for a bullet on that agent + model. If it records haiku failing or needing reruns in this repo, keep the frontmatter default (sonnet). Log every fresh spawn to `.team/<task>/spawns.tsv`, including in the fix lane, with its `tok:` count when the agent finishes ([memory-model.md](memory-model.md#checkpoint)). This only ever moves an agent between `haiku` and `sonnet`, never above
- **Unknown stack**: a `blocked` hand-off with a `Researcher` blocker `stack-unknown: <framework> <version>` is handled by [stack-learning.md](stack-learning.md): a `researcher` stack note at `model: "haiku"`, effort `low`, once per framework per repo, never per task, never escalated to L2/L3 or a normal research run. No builder has web access for it (the architect's and devops's web access is for provider and infrastructure facts only, capped in their own references)
- **Never downgrade** `code-reviewer`, `architect`, or `devops` in production mode — a miss there costs more than the tokens saved
- **Effort tiers**: effort is a separate axis from model — how hard the agent thinks, not which model thinks. Allowed: `low`, `medium`, `high` — never `xhigh` or `max`. Agent frontmatter sets the default (`architect`, `code-reviewer`, `devops` = high; `backend-dev`, `frontend-dev`, `designer`, `diagrammer`, `qa-tester` = medium; `researcher`, `docs-writer`, `product-manager` = low; product-manager in present mode is spawned at `medium`, since turning plans into a persuasive, sourced deck is judgment work). When spawning fresh, decide the effort from these signals — read them from files, don't judge by feel:

  | Signal | Read from | Effect |
  |---|---|---|
  | High impact: touches auth, payments, data migrations or secrets | `contract.md` (schemas, file ownership) | `high`, overrides everything below |
  | Assumed requirements: `[assumed]` items | `ac.md`, `requirements.md` | +1 level |
  | Stalled: the same blocker id open in ≥ 2 consecutive rejections | `checkpoint.md` `## Open blockers` | +1 level |
  | Exact fix: every open bug names file + line + expected fix (also re-running existing tests) | hand-off `blockers[]` | −1 level |

  Combine: start at the role default, add the effects, cap the net move at one level either way, stay within `low`–`high`. The same rules are checked offline by `npm test`
  - **Never lower** the effort of `code-reviewer`, `architect` or `devops` in production mode, same reason as model
  - A `SendMessage` fix round keeps the agent's current effort; to change it, spawn fresh and point it at `checkpoint.md`
  - Record the signals used and the resulting effort in checkpoint `## Run profile` (one line); skip the line when the default applies
