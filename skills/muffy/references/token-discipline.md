# Token discipline

- **Prompt template**: every subagent prompt is only this, no pasted file contents (parsed shape: [prompt-envelope.schema.json](../schemas/prompt-envelope.schema.json)). Team-folder paths in `Read:` and `Write:` go under the feature worktree (`.worktrees/feature-<task>/.team/<task>/…`), never bare `.team/<task>/…`, which resolves in the main checkout:
  Order is fixed so the prefix stays cacheable across rounds: constant lines first, per-spawn lines after `Final message:`, `Hand-off shape:` last ([spawn-prompt.md](spawn-prompt.md)). Shown here in that order:
  ```
  Task: <task>  Brain: <brain>  [Vault: <vault> — researcher only]  [Mode: 1 | 2 | 3 — devops; onboard | stack-note — researcher; onboard — architect]  [Profile: fix — fix lane only; Read: fix.md replaces ac/contract/brief/design]  [Scope: internal | ui-only | ui+logic | logic-only — change lane only, `--scope`; internal: Read ac.md + contract.md, no brief/design]
  [Worktree: <path> · Branch: <branch> — frontend-dev, backend-dev, qa-tester, devops mode 2; created by the Orchestrator (setup.md step 7)]
  Don't touch: <paths/scope>
  Commit trailer: <verbatim attribution line the harness gave the Orchestrator for this session — never typed from the skill, never a model name taken from a file — passed to every agent; every commit ends with it>
  Final message (silent execution; code-reviewer exempt: its message is saved as review-<n>.md, ≤ 120 lines): on success (`status: done`, no blockers, checks passed) only the one-line JSON hand-off block, no prose. Prose ≤ 8 lines and ≤ 1,200 characters only on an error, `blocked`/`not-ready`, or a decision for the Orchestrator or user (blocker ids `B-n`, from round 1 on). Details belong in files. End with the one-line JSON hand-off block; do not Read handoff.schema.json, the shape is in the next line
  Goal: <one line>
  Done when: <one observable result that ends this step, e.g. "handoff validates and every AC-n in ac.md is listed">
  Read: <paths>
  Write: <paths>
  [Announcement: yes — docs-writer only, when the user opted in at pause:scope]
  [PR diagram: yes — frontend-dev/backend-dev only, when the user asked for step 5b ("draw the PR diagram")]
  [Human approved: <date> — docs-writer step 11 only, after the step-10 Human gate]
  [Test level: L0–L4 — qa-tester only; copy the row from test-levels.md]
  [Full regression: approved — qa-tester only, after pause:full-regression; absent means qa-tester must run scoped tests only]
  [Checkpoint: .team/<task>/checkpoint.md — from round 2 on; read only ## Goal and ## Open blockers]
  Hand-off shape: <the one-line example below, with this spawn's role, task, step and round>
  ```
- **Build the prompt with the script**: `node "<muffy>/scripts/make-envelope.mjs" --role <role> --step <step> --round <n> --task <task> --brain <brain> --goal "…" --done-when "…" --read a.md,b.md --write <paths> --dont-touch <paths> [--worktree … --branch …] --trailer "<attribution line>"` prints the template above, fills in the hand-off path and the hand-off shape, and validates the envelope against the schema first. Typing the template by hand costs ~1 KB of your output per spawn and drifts; use the flags (`--mode`, `--profile`, `--test-level`, `--checkpoint`, `--announcement`, `--pr-diagram`, `--full-regression`, `--human-approved` cover the optional lines)
- **Sub-agents run silent**: a successful run returns the JSON hand-off line alone (compact structured output: `status`, `paths_written`, `ac_ids_done`, `blockers`, `quality_checks`, one-line `summary`); prose appears only for an error or a decision. Prose on a clean `done` is over the cap: ignore it and route on the JSON. Facts that used to ride in the message are read from where they live: a PM or designer's open questions from `questions[]` (`needs-input`) or `summary`, a researcher's level from `brief.md`
- **Final report is capped, and the cap is enforced by you**: measured on 224 real hand-backs, the average was 4.4 KB against a 10-line rule. Every hand-back enters your context for the rest of the session. Over the cap (more than 8 lines or 1,200 characters before the JSON), do not act on the prose: route on the JSON, and on the next spawn of that role repeat the cap in `Final message:`. A report is never copied into another prompt
- **Bash output stays out of the conversation**: a command whose output may pass ~20 lines (tests, builds, `git log`/`git diff`, installs, validators on a whole folder) runs through `node "<muffy>/scripts/run-quiet.mjs" [--tail N] -- <command>`. It writes the full output to a log file and prints only `exit=<code> lines=<n> log=<path>`, the last lines and the error-looking lines. Open the log with a narrow `Grep` or a `Read` with `offset`/`limit` only when that is not enough. Prefer one command that does several things over several commands that each print. Scripts in `scripts/` already print a verdict line, not a report
- **Writing JSON on Windows**: never write a hand-off or escalation file through a heredoc, `printf` or `echo`: backslashes in Windows paths break twice that way. Use the Write tool, or `JSON.stringify` in node, and then run the validator right away
- **Hand-off example**: put this in every prompt's `Final message:` line so the agent copies a valid shape (values are the allowed ones; `status` is never `ready`, `step` is a string, `blockers` is an array, `owner` is never `Orchestrator`; `decisions` is required for designer, architect, product-manager, frontend-dev, backend-dev, devops and docs-writer outside present mode, see [spawn-prompt.md](spawn-prompt.md)):
  ```json
  {"role":"backend-dev","task":"<task>","step":"4","round":1,"status":"done","paths_written":["src/a.ts"],"ac_ids_done":["AC-1"],"decisions":[{"id":"D-1","decision":"…","why":"…"}],"blockers":[],"quality_checks":{"passed":true,"failed":[]},"summary":"one line"}
  ```
  A blocker looks like `{"id":"B-1","problem":"...","file":"src/a.ts:12","owner":"BE"}` with `owner` one of FE, BE, Docs, Devops, Architect, Designer, PM, Researcher
- **Agents with `Write` save their own hand-off**: put `.team/<task>/handoff/<step>-<role>-r<round>.json` in the `Write:` line of every agent except `code-reviewer`; the agent writes and validates it (its own guardrails say how). You then only validate it, or, for `code-reviewer` (read-only, no Bash), save the block from its message. Agents with check-only Bash (`architect`, `designer`, `product-manager`, `docs-writer`, `researcher`) never commit: you commit their files
- **Deferred writes**: the harness can refuse a subagent's write of a report-style file (plan, contract, brief, review, brain note) with `Subagents should return findings as text, not write report files`. The agent then returns each file as a `<<<FILE path>>> … <<<END>>>` block and lists the paths in `deferred_writes` (and `paths_written`). You write each block verbatim with the `Write` tool, under the feature worktree like any team-folder path, before you validate the hand-off; a hand-off JSON the agent could not save is saved from its message the same way. Never re-spawn the agent, change its tools or route around the refusal to get the file written by it, and do not edit the content beyond what the block holds. Record `deferred writes: <paths>` in checkpoint `## Status`, then commit those files as for any check-only-Bash agent. A block that is cut off or lacks `<<<END>>>` → spawn the role fresh for that file only, with the cut-off hand-off path in the prompt (no `SendMessage`; the flow is silent)
- **Hand-off block**: every agent ends with one line of JSON. It is saved as `.team/<task>/handoff/<step>-<role>-r<round>.json` (by the agent, see above) and `node "<muffy>/scripts/validate-handoff.mjs" <file>` runs before you act on it. Route on the JSON (`status`, `verdict`, `blockers[].owner`), not by re-reading prose. Invalid → fallback ladder in [loops.md](loops.md)
- **Lazy loading**: read a reference only at the step that needs it: `SKILL.md` links each one to its step; `closing.md` only at step 12; `hooks-enforcement.md` only at setup; `loops.md` only when a reject/fail happens; this file and `memory-model.md` once at setup. Agents follow the "Load on demand" table in their own definition; don't ask an agent to "read all references"
- **Fix rounds are fresh spawns, never `SendMessage`** (the fix lane and the full flow are both silent): only that owner's blockers/bugs go in, as a path in `Read:` to the hand-off file that holds them. The new spawn reads the earlier hand-off files named in its prompt (`handoff/4-backend-dev-r<n>.json`, `4a-debugger-r<n>.json`, `4b-auditor-r<n>.json`), including their `decisions[]`, so agents talk only through hand-off JSON and the Orchestrator can validate and diff every round. Only requirements, present and diagram rounds still continue the same agent ([spawn-prompt.md](spawn-prompt.md))
- **Incremental diffs**: export each round as `diff-<n>.patch` containing only the changes since the last review
- **Topic-split review diffs**: when `diff-<n>.patch` is over ~1,500 lines or touches more than ~15 files, run `node "<muffy>/scripts/split-diff.mjs" .team/<task>/diff-<n>.patch` (it checks the size itself and does nothing when the diff is small). It writes one patch per topic, `diff-<n>-<topic>.patch`, plus `diff-<n>-index.md`; give `code-reviewer` the topic files in `Read:` instead of the whole `diff-<n>.patch`. A topic is one reviewable concern: a vertical slice (data/migration, API routes + their DB layer, client queries/hooks, UI components, infra/docs/smoke). The script keeps each test with the code it tests, splits by directory depth until a topic fits, and verifies that every file lands in exactly one topic with no bytes lost. Override its grouping with `--rules rules.json` (`[{"topic", "match": regex}]`) when the path layout hides the real concern. Limits: `--max-lines`, `--max-files`. Example, `manual-asset-mapping` (67 files, 8,164 lines) → 10 topics such as `db-migration`, `nms-ingest-routes`, `nms-ingest-db`, `nms-dashboard-shared`, `infra-docs-smoke`. Keep the full `diff-<n>.patch` for docs-writer; fix rounds are small and stay one file
- **Do not Read `handoff.schema.json`** (9 KB, was read by 31 agents in a sample of 150): the shape is in the prompt's `Hand-off shape:` line and `validate-handoff.mjs` prints exactly what to fix. Read the schema only when a validation error does not say enough
- **Turn budget**: an agent that has made about 80 tool calls without finishing stops, writes what it has, commits, and hands off `status: not-ready` with a blocker `B-n` saying what is left; the Orchestrator answers with a fresh spawn that points at `checkpoint.md`. In the sample, `designer` ran 163 turns and `backend-dev` 138 on average, and context grows with every turn, so one long run cost more than two short ones. `docs-writer` and `qa-tester` are expected to finish in under 60
- **Compact at gates**: after step 3 (planning files committed), after step 7 (QA done) and right before the Human gate, write `checkpoint.md` and run `/compact` with the focus line `keep: task, step, open blockers, next:`. After a compact, read only `checkpoint.md`. Do not re-invoke `/muffy` to "reload" the skill: once `SKILL.md` is in the session, follow it from where you are (the sample re-loaded it 44 times, 7 KB each)
- **Big shared docs are read by section**: `docs/architecture/baseline.md` (and its `baseline/` folder, see [onboard.md](onboard.md#baselinemd)), `docs/design-system/README.md`, `contract.md` and large source files (`Grep -n` for the heading or symbol, then `Read` with `offset`/`limit`). Put the section names in `Read:` (`baseline.md#conventions`) instead of the whole file when you know which one the agent needs. Re-reading a file already read in the same run is a defect unless it changed
- **Read narrowly**: for gates and traceability checks, grep or read only the section needed (e.g. the `AC id →` table) instead of whole files; don't re-read a file you already checked unless it changed
- **Don't relay**: never copy one agent's output into another's prompt: give the path
- **Checkpoint instead of history**: from round 2 on, point to `checkpoint.md`; don't replay earlier rounds ([memory-model.md](memory-model.md#checkpoint))
- **Follow a link, don't load the folder**: an agent opens `rounds/<step>-r<n>.md` only when its own prompt names that label or path. Never Read or Glob all of `rounds/`
- **Model tiers**: only `haiku` and `sonnet` are allowed, never pass `opus` or `fable`. There are exactly two exceptions. (1) `auditor` (fix lane), whose frontmatter default is `opus` so that it runs on a different model from the `debugger` it audits; pass the default, never change it. (2) `code-reviewer`, which may run on `opus` only when the High impact signal below holds (`contract.md` touches auth, payments, data migrations or secrets), in production mode, in any lane and any round; `make-envelope.mjs` prints `model=opus` in that case and nowhere else. No other role, no other signal and no judgment call by the Orchestrator ever passes `opus`: a code-reviewer on a task without the High impact signal runs on its `sonnet` default. Agent frontmatter sets the default (`docs-writer` = haiku, `auditor` = opus, the rest = sonnet). Every silent-flow round is a fresh spawn, so pass `model: "haiku"` for:
  - `qa-tester` re-running existing tests only (no new tests to write)
  - `frontend-dev` / `backend-dev` fix rounds where every bug names a file + line and the expected fix
  - `researcher` when the run profile asks for codebase-only / minimal research
  - `debugger` step 4a (fix lane) when the symptom already names the file and line; see [fix-profile.md](fix-profile.md)
- **`docs-writer` stays on sonnet when the docs restate numbers or a policy list** (refused classes, limits, AC counts, test numbers): the haiku default is for prose; a list that must match the code or an AC needs the stronger model, and a repo-wide grep for the same claim
- **Learn from this project's spawn history**: before passing `model: "haiku"` for a case above, check `<brain>/project.md` `## Lessons` for a bullet on that agent + model. If it records haiku failing or needing reruns in this repo, keep the frontmatter default (sonnet). Log every fresh spawn to `.team/<task>/spawns.tsv`, including in the fix lane, with its `tok:` count when the agent finishes ([memory-model.md](memory-model.md#checkpoint)). Lessons only ever move an agent between `haiku` and `sonnet`; they never raise it to `opus`, which only the two exceptions above can
- **Unknown stack**: a `blocked` hand-off with a `Researcher` blocker `stack-unknown: <framework> <version>` is handled by [stack-learning.md](stack-learning.md): a `researcher` stack note at `model: "haiku"`, effort `low`, once per framework per repo, never per task, never escalated to L2/L3 or a normal research run. No builder has web access for it (the architect's and devops's web access is for provider and infrastructure facts only, capped in their own references)
- **Never downgrade** `code-reviewer`, `architect`, `devops` or `auditor` in production mode: a miss there costs more than the tokens saved
- **Effort tiers**: effort is a separate axis from model, how hard the agent thinks, not which model thinks. Allowed: `low`, `medium`, `high`, never `xhigh` or `max`. Agent frontmatter sets the default (`architect`, `code-reviewer`, `debugger`, `devops` = high; `backend-dev`, `frontend-dev`, `designer`, `diagrammer`, `qa-tester` = medium; `auditor`, `researcher`, `docs-writer`, `product-manager` = low; product-manager in present mode is spawned at `medium`, since turning plans into a persuasive, sourced deck is judgment work). When spawning fresh, decide the effort from these signals, read them from files, don't judge by feel:

  | Signal | Read from | Effect |
  |---|---|---|
  | High impact: touches auth, payments, data migrations or secrets | `contract.md` (schemas, file ownership) | `high`, overrides everything below |
  | Assumed requirements: `[assumed]` items | `ac.md`, `requirements.md` | +1 level |
  | Stalled: the same blocker id open in ≥ 2 consecutive rejections | `checkpoint.md` `## Open blockers` | +1 level |
  | Exact fix: every open bug names file + line + expected fix (also re-running existing tests) | hand-off `blockers[]` | −1 level |

  Combine: start at the role default, add the effects, cap the net move at one level either way, stay within `low`–`high`. The same rules are checked offline by `npm test`. **Don't judge it yourself**: `make-envelope.mjs` reads these signals and the haiku cases and `## Lessons` from the task's files, and prints `Spawn: model=<m> effort=<e>` on stderr. Pass those two values to the Agent call as they are. Add `--rerun-only` (qa), `--minimal-research` (researcher) or `--line-known` (4a) when one of those cases applies, since no file records them. If the files read a signal wrong (e.g. the contract only mentions auth), use `--force highImpact=false`. To get the effort alone: `node "<muffy>/scripts/next-action.mjs" effort --role <role> [--high-impact] [--assumed] [--exact-fix] [--stalled <n>]`
  - **Never lower** the effort of `code-reviewer`, `architect` or `devops` in production mode, same reason as model
  - **`auditor` is pinned** to `opus` at effort `low`: no signal raises or lowers it
  - A fresh round recomputes effort from the signals above; a round continued with `SendMessage` (requirements, present, diagram) keeps the agent's current effort
  - Record the signals used and the resulting effort in checkpoint `## Run profile` (one line): copy the `Run profile line:` that `make-envelope.mjs` prints. When it prints none, the default applies and no line is needed
