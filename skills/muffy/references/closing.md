# Closing a task

Read this only at step 12, or when the user stops the flow.

1b. **Promote durable knowledge to the repo**: decisions not yet in an ADR → ADR; design changes → `docs/design-system/`; stack learnings → `docs/stack-catalog.md`; remaining phases → `docs/plan/<task>.md` backlog. Nothing future work depends on may live only in `.team/` or the vault
2. **Update `<brain>/tasks/<task>.md`**: status, commit/PR, links to plan + ADR, `## Lessons` (what went wrong / what worked / what to do differently — short bullets), `## Open issues` (pending + backlog phases), `## Usage`: one line per agent that ran — `role · model · approx tokens` (the `tok:` value logged in `spawns.tsv` note), plus the Orchestrator's own line. The `tok:` values are cumulative per agent ([memory-model.md](memory-model.md#checkpoint) Spawn log): take the last value of each agent (a `SendMessage` continuation is the same agent), then sum those; two spawns of the same role in different modes are two agents. Read the Orchestrator's own line from `/context` as the last step before you write the note, and if you could not, write it as `at least <n> (mid-run reading)`. Totals are summed from those lines, never estimated freehand. `n/a` is allowed only when the runtime gave no count for that agent; if it reported one, writing `n/a` is a violation. Closing is never abbreviated, in the fix lane too: write the full note, `## Usage` and the Lessons tally included
   - Also tally `.team/<task>/spawns.tsv` by `agent · model`: add one bullet to the task note's `## Lessons` per pair that has a clear signal (e.g. `qa-tester · haiku · re-run only: 4/4 pass`, or `backend-dev · haiku: 2/3 sent back`). Skip pairs with fewer than 3 spawns (count agents, not log lines: a continued agent is one spawn; count its extra rounds as reruns); update the existing bullet's counts instead of adding another. If `spawns.tsv` is missing or short of spawns that happened, say so in the final message (step 6) and rebuild what you can from the hand-offs; never skip this silently
3. **Consolidate `<brain>/project.md`**:
   - `## Tasks`: set this task's status (`in progress` → `done`; resume finds unfinished work by this) + one-line outcome, linking `[[tasks/<task>]]`
   - `## Lessons`: merge this task's lessons — reword an existing bullet instead of adding a near-duplicate; each bullet has date + source wikilink
   - Move lessons now enforced by an ADR, agent rule or code, or no longer true, to `## Retired lessons` with the reason; keep `## Lessons` ≤ 30 bullets
   - `## Open issues`: add new, remove ones this task resolved
   - **Daily note (optional)**: only if `<vault>/daily/` exists, append one bullet under `## Log` of `<vault>/daily/YYYY-MM-DD.md` (skip if the file is missing; never create it): `- [[Projects/<repo-name>/tasks/<task>]]: <status> · <one-line outcome>`. Append only, never edit other lines, no secrets
4. **Mark the checkpoint closed**: rewrite `checkpoint.md` with `## Status` = `closed` (so a resume without a vault skips it)
5. **`.team/<task>/`** stays committed as the audit trail; `diff*.patch` is gitignored (regenerable)
6. **Final message to the user**: status, commit/PR, staging/production result, links to plan + ADR, diagram links (from the task note's `## Diagrams`), open issues, and any step that was skipped or failed — stated as such
