# Changelog

## Unreleased

### Changed

- **`code-reviewer` may run on `opus` for high-impact work only.** The model rule used to allow `opus` for the fix-lane `auditor` alone, yet an Orchestrator passed `model: opus` to a code-reviewer on a login task. That is now the one allowed case: `spawnProfile` returns `opus` for `code-reviewer` in production mode when `contract.md` touches auth, payments, data migrations or secrets (the High impact signal), and `sonnet` otherwise. No other role or signal reaches `opus`, and Lessons never raise a model. The frontmatter default stays `sonnet`. Checks in `scripts/eval.mjs` (spawn-profile cases, `OPUS_ON_HIGH_IMPACT` drift).
- **Infrastructure is the human's, not devops's.** Onboard and setup no longer ask the infrastructure question, `infra:` is gone from checkpoints and `project.md`, and devops no longer proposes hosting options or applies infrastructure practices (`infrastructure-options.md`, `infrastructure-best-practices.md` and devops web access removed). `deploy.md` keeps `## Pinned runtime`, `## Target`, `## Files devops owns` and `## Risks`; devops still pins the runtime, owns local Dockerfile/compose/CI files and smoke-builds on docker local.
- **No staging or production in any lane.** Work ends on docker local at the Human gate; deploying is the user's step. Steps 8 (docs review) and 9 (staging) are gone and step 11 is now `docs-writer` instead of `devops` production; ids are kept so hand-offs and scripts keep one numbering. `pause:staging-credentials`, the staging question at `pause:scope`, the `staging_none` smoke trigger and devops mode 3 (and its `fix-profile.md`) are removed. The `ops` route is now local infra only; a deploy or rollback request is answered with the Deploy hand-off instead of routed.
- **`docs-writer` runs last, after the Human gate approves,** in the full flow, lite, fix and the new redesign lane. It writes only what the diff touched, with no `TBD` and no second round, ends `release-notes.md` with a **Deploy hand-off** and self-checks its sources; no `code-reviewer` pass. Fix and lite may skip it when nothing a user sees changed, there is no migration or config and no doc mentions the changed part (`docs skipped: <reason>`). The gate summary at step 10 no longer shows release notes or a staging result.
- **The lite and redesign lanes are one change lane.** `references/change-profile.md` holds both, told apart by a scope: `internal` (was lite: no plan or design gate, 15-file limit, quick baseline) or `ui-only`, `ui+logic`, `logic-only` (was redesign). `lanes.mjs` has three lanes, feature, fix and change, with `laneSpec(lane, scope)`; `lite` and `redesign` are aliases, so `/muffy lite` and `/muffy redesign` still work and every lane line written before (`lane: lite`, `lane: redesign (<scope>)`, `lite: skipped …`, `redesign lane (<scope>): …`) reads as the change lane and scope it means. A change line with no or an unknown scope fails closed: gated, like a scopeless redesign. Routing, triage (`triage change`; `triage lite` is the same) and every scenario keep their outcomes (84 checked before the files were rewritten; `lite`/`redesign` became `change`). One prompt header scheme: the fix lane sends `Profile: fix`, the change lane `Scope: <scope>` (`--profile lite` becomes `Scope: internal`), and the agent references key on it. `lite-profile.md` and `redesign-profile.md` remain as pointers.
- **One lane table, `skills/muffy/scripts/lanes.mjs`.** Step order, the skips and never-skip steps of each lane (and each redesign scope), which lanes are gated and the fix and lite file limits now live in one module; `gate-rules.mjs`, `next-action.mjs`, `check-all.mjs`, `diff-signals.mjs` and `checkpoint.mjs` read it. The lane line in checkpoint `## Run profile` is written by the new `checkpoint.mjs profile <dir> <lane> [--scope] [--skip]` as `lane: <id>[ (<scope>)] · skipped …`; older wordings still parse, so existing tasks resume. `check-all` reads the lane from the checkpoint when `--profile` is left out, `make-envelope.mjs --scope` puts `Scope:` in the prompt header, and the designer and frontend-dev references now say what to do with it (`needs-logic:` blocker). `resume.md` opens the redesign reference too. Checks in `scripts/lib/lane-table-evals.mjs`.
- **Full flow is the last route, not the default.** Decision step 6.4 is replaced: a change to something the product already has goes to redesign, a capability it lacks goes to full flow, and anything vaguer is asked in rounds until one route fits. "ทำเลย" or "แล้วแต่" picks the smallest route that fits.

### Added

- **Headless answers to several questions.** A `gate.json` with up to 4 questions is answered by one line whose `<answer>` holds the answers in question order, separated by ` | ` (a multiSelect part keeps its `, `). `checkpoint.mjs answer` maps each part to its question by position and prints `answer.<n>=<header>: <answer>`; a part count other than the question count exits 2 and writes nothing, so the pause and `gate.json` stay. A single question is unchanged. Checks in `scripts/lib/headless-evals.mjs`.

- **Headless gates** (`MUFFY_HEADLESS=1`, `references/headless.md`). Under `claude -p` there is no question tool, and muffy used to answer `pause:scope` itself or stop with the question as prose. Now every question goes through `checkpoint.mjs ask`: the Orchestrator drafts the `AskUserQuestion` input in `.team/<task>/gate.json`, the script checks it against `schemas/gate.schema.json`, adds `gate`, `task` and `created_at`, replaces the `paused at` line (never a second one), and prints `muffy-status: waiting:<gate>` for the final message after the commit. Rule H2 (only with `MUFFY_HEADLESS_POLICY=self-heal`): `pause:scope` passes when triage passed and the AC come from the request (`auto: approved by Investigate (@<MUFFY_TRIGGERED_BY>) · rule H2`); the first audit `need-validation` re-runs on its own (`auto: re-diagnose · rule H2`); a second non-confirm, a `reject` and `pause:human-gate` always wait. `/muffy resume` runs `checkpoint.mjs answer` first: it consumes `<gate> answered: <answer> by <who> (<source>) <ISO time>` from `## Status`, clears the pause, records gate 2b/3c or the accepted audit risk, appends a `<gate> answer consumed` marker (the person's line stays as written) and removes `gate.json`. New named pauses `pause:audit`, `pause:escalation` and `pause:question`. Without `MUFFY_HEADLESS` nothing changes (`ask` prints `next=ask-user`). Checks in `scripts/lib/headless-evals.mjs`.
- **Plugin install** (1.4.0). The repo is now a Claude Code plugin and a marketplace (`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`): `/plugin marketplace add Axebee-Security-Platforms/muffy`, then `/plugin install muffy@muffy`. The skill, agents and scripts stay in the plugin folder. The marketplace is named `muffy`, because `harmonyx` belongs to the spright repo's marketplace and a name maps to one source.
  - **Setup.** A new `/muffy:setup` skill runs `install.mjs <repo> --plugin`, which copies nothing and writes only `settings.local.json`, the `.gitignore` lines and the scan.
  - **Paths.** Script and template paths in the skill, the agents and every reference are written `<muffy>/…`. `SKILL.md` defines `<muffy>` through `${CLAUDE_SKILL_DIR}`, and each agent through `${CLAUDE_PLUGIN_ROOT}`; the copied install rewrites `${CLAUDE_PLUGIN_ROOT}` to `.claude`, so both installs work. The default `agents/` scan loads the agents; `plugin.json` has no `agents` key.
  - **Guards.** They ship in `hooks/hooks.json` with `--plugin` and stay off until the project sets env `MUFFY_GUARD=1` (`plugin-gate.mjs`; `/muffy:setup --with-guard` sets it). The Bash allowlist accepts the plugin's own absolute script path, quoted or not, with either slash, and still refuses a look-alike `skills/muffy/scripts/` folder anywhere else.
  - **Other script changes.** `sync-worktree.mjs` prints `nothing to sync` when the repo has no copied skill. The Orchestrator spawns `muffy:<role>` when the Agent tool lists it.
  - **Wrapper gap closed.** The full-regression and test-level guards now judge the command after `--` in `run-quiet.mjs`, whatever folder the wrapper runs from. Before, `node …/run-quiet.mjs -- npx vitest run` let a qa-tester run the whole suite unapproved, or e2e at L1.
  - **Agent reference files moved to `agent-references/`** (1.4.1; was `agents/references/`). A plugin loads every `.md` under `agents/`, subfolders included, so each reference file showed up as an agent, such as `muffy:references:architect:workflow`. `agents/` now holds only the 13 definitions. Their links point to `../agent-references/…`, and the copied install puts the folder at `.claude/agent-references/`. `--clean` removes both the new folder and the old `.claude/agents/references/`.
  - **Setup removes a copied install** (1.4.2). `/muffy:setup` removes, by default, an older copied install in the repo: `.claude/skills/muffy/`, muffy's agent files (from `MANIFEST.json`), `.claude/agent-references/`, `.claude/agents/references/`, and the hooks in `settings.local.json` that run `.claude/skills/muffy/scripts/*`. Before, two `/muffy` skills and two sets of agents loaded side by side, and deleting the copy by hand left hooks that failed on every tool call. The user's own agents and hooks stay. Hooks in a team `settings.json` are reported, not edited. `--keep-copy` keeps the copy; `--dry-run` previews.
  - **No code comments** (1.4.3). `frontend-dev` and `backend-dev` write no comments except a function name and description; `code-reviewer` rejects a diff that adds any other comment.
  - **Bump the version for every release.** `plugin.json` pins `version`, so `/plugin marketplace update` installs a change only after the version moves. 1.4.1 carries the reference-file move to installed plugins.
  - **Checks** are in `scripts/lib/plugin-evals.mjs`. Doc checks that pinned `checkpoint.mjs profile …` now match the quoted `checkpoint.mjs" profile …`.
- **Special flows, reached by plain words, no new command.**
  - **Diagnose only** ("แค่หาสาเหตุ", "just find the cause"): the fix lane with a stop point. `checkpoint.mjs profile … fix --scope bug --until 4b` writes `· until 4b` on the lane line; once 4b is accepted `check-all` and the loop answer `close:stop-point`, a step-4 spawn is refused, and a `needs-full-flow` diagnosis is reported with its `promote_to` as advice instead of promoted. `closing.md` has the stopped-at-a-stop-point close.
  - **Verify lane** (`references/verify-profile.md`): review, QA, the Human gate and docs on a branch someone already wrote, on a copy `verify/<task>`; the requester's branch is never edited or merged. A reject or a QA fail answers `ask:verify-fix`: fix on the copy, or report only.
  - **Upgrade lane** (`references/upgrade-profile.md`): a version bump of a dependency or runtime already in the manifest. Researcher (changelog), the upgrade ADR approved at 3c, 3d always, full regression offered; 2b is skipped on record. "Upgrade React to 19" now routes here instead of the full flow; a new dependency still goes to the full flow.
  - **Smoke and measure** are route rows, not lanes: a stack smoke on a branch is the `ops` route (devops mode 2), and the internal triage's missing before-number offers to measure it first.
- **A promotion ladder instead of a jump to the full flow.** A debugger's `needs-full-flow` diagnosis now carries `promote_to` (`change-internal`, `change-visible` or `full`; missing = `full`, so older hand-offs behave as before), and the loop answers `promote:change-internal`, `promote:change-visible` or `promote:full-flow`. An internal change whose `PM` or `Designer` blocker names a visible change moves to a visible scope instead of the full flow, and the full flow offers one rung down when `product-manager` finds nothing a user sees changes. `run-profile.md` has the ladder in one table. Step-4 promotions of a fix (over 5 files, an `Architect` blocker) still go to the full flow. After any promote out of the fix lane, `check-all` leaves the task's old 4a/4b hand-offs out of the loop and the gate check: before, the leftover `needs-full-flow` promoted the task again at every later step, and a promote to a gated lane tripped gate 2b on the old 4a hand-off.
- **A cosmetic fix skips the 4b audit.** The fix lane has a scope, `bug` or `cosmetic`, written by `checkpoint.mjs profile … fix --scope <kind>` from `fix.md`'s `Kind:`. A cosmetic fix (existing tokens only) has no cause whose evidence needs grading, so 4b is skipped and the debugger runs on `haiku`; the audit guard, `check-all` and the loop read the scope. The skip holds only while 4a rates the severity `low`: above that it is not only the look, step 4 waits for the audit, and the Orchestrator switches the scope to `bug`. A bug, and a fix line with no or an unknown scope, still need 4a and 4b. New mock scenarios: `fix-promotes-to-change-internal`, `fix-promotes-to-change-visible`, `fix-cosmetic-skips-audit`, `fix-cosmetic-above-low-needs-audit`, `fix-bug-cannot-skip-audit`.
- **One way in: `/muffy <request>`, and a bare `/muffy` for the menu.** Before anything starts the requester sees a plan card from `next-action.mjs plan-card <lane>` (built from `lanes.mjs`): what is being done, the steps in order, what is skipped and why, where it stops, in Thai or English, with no lane name. Its question (go / stop earlier / bigger or smaller) rides as the first question of `pause:scope`, so it costs no extra round; redesign asks its scope first, in plain words ("the look only / the look and the rules / the rules only"). A bare `/muffy`, `/muffy todo` and `/muffy resume` with no task show `references/menu.md`: what muffy knows about the project, the unfinished tasks, and what else it can do. `route.md` gains the plain questions for an unclear code change ("is something broken? / does it exist already? / will a user see a change?") and a Stop points table ("แค่วางแผน", "ยังไม่ต้องเขียนโค้ด"). The README leads with what to type and what happens; lane commands are listed as shortcuts. Checks in `scripts/lib/entry-evals.mjs`.
- **Onboarding happens on its own.** Setup step 3 now runs in every lane (fix, lite and redesign included) through `next-action.mjs baseline --lane <lane>`, which reads `check-baseline.mjs --json` and prints what to do. No baseline → one question, "look first, then carry on": the request is saved to `.team/onboard/pending-request.md`, onboard runs at the depth the lane needs (fix and lite get a quick baseline with Stack, Layout and Commands and no review; redesign and the full flow the full one), and its new step 0f picks the request back up. A yellow baseline is refreshed without a question (no 0d while the Stack is unchanged); red still asks. 0d asks each `[verify]` item on its own and shows the ADR and agent-context block as a diff. `check-baseline.mjs --json` reports `depth`. A quick onboard and a silent refresh have no 0d, so the Orchestrator commits only the baseline files on the current branch right after 0b (`docs(baseline): …`); setup cherry-picks that commit onto `feature/<task>` when the base picked at `pause:scope` is another branch. The installer scans by default (`--no-scan` to skip) and points at `/muffy <request>` instead of `/muffy onboard`. Checks in `scripts/lib/onboard-evals.mjs` and `evals/baseline-scenarios.json`.
- **Redesign lane** (`/muffy redesign`, `references/redesign-profile.md`) for changing an existing screen, UX flow or business-logic rule. The scope (UI only, UI + logic, logic only) is always asked at `pause:scope`; each scope runs only the agents it needs, QA is L3 limited to the touched paths, the AC and design are approved together for UI only, and `pause:scope-upgrade` handles a UI-only run that turns out to need logic. `gate-rules.mjs`, `checkpoint.mjs` and `gate-summary.mjs` know the lane; checks in `scripts/lib/redesign-lane-evals.mjs`.

- **Designer UX/UI rules in priority tiers.** New `agents/references/designer/ux-ui-rules.md` ranks the rules P1 (accessibility) to P10 (charts), adapted from the `ui-ux-pro-max` skill. CRITICAL and HIGH tiers (P1-P5, P9) block the hand-off, MEDIUM tiers (P6-P8) are recorded in `design.md`, LOW (P10) is advice. Each rule has an id that quality checks, the heuristic evaluation and the step 3c review cite.
- **`ux-search.mjs` for the designer.** A Node port of the `ui-ux-pro-max` BM25 search (MIT, notice in `skills/muffy/THIRD_PARTY_NOTICES.md`) over five tables in `skills/muffy/data/ux/`. Read-only. `guard-bash-allowlist.mjs` lets only `designer` run it; every other guarded role is refused.

### Fixed

- **Worktrees were never removed.** Agents were told the Orchestrator removes them, but no step did, so every task left `.worktrees/*-<task>` behind. New `remove-worktrees.mjs` removes ops, fe, be and qa when the Human gate approves and the feature worktree at closing (kept on a stop-point or report close, for the resume). It never forces: a dirty, unreachable or locked worktree is kept and reported, and branches stay. `check-all` flags a leftover role worktree at step 11 (`next=remove:worktrees`). Worktree agents now commit everything and stop what they started before each hand-off.
- **The qa worktree had no branch.** `setup.md` cut it "from the reviewed branch", which is already checked out in the feature worktree, so QA's commits could sit on a detached HEAD. It is now `qa/<task>`.
- **A verify reject went straight to a dev from the loop call `loops.md` gives.** `next-action.mjs loop` took the lane only from `--profile`, and the documented flags listed `fix|change`, so a verify task answered `fix:<owner>` instead of `ask:verify-fix` (and an upgrade task ran as the feature lane). With no `--profile` it now reads the lane, scope, stop point and skips from the checkpoint beside the hand-offs, as `check-all` does; `loops.md`, `quality-checks.md` and the script usage lines list `verify|upgrade`. New evals in `scripts/lib/special-flows-evals.mjs`.
- **The description named no trigger for the upgrade and verify lanes** ("bump", อัปเกรด, "review and test before merge", ตรวจให้ครบ), so such a request might never reach the router. Added within the 1024-character limit.
- **Promotion text from before the ladder.** `SKILL.md`, `loops.md`, `change-profile.md`, `run-profile.md` and the README said a fix (or an internal change with a `PM`/`Designer` blocker) goes to the full flow, and `SKILL.md` said 4b is never skipped; they now point at the promotion ladder and the cosmetic 4b skip.

- **Third-party notices in one place.** The ui-ux-pro-max MIT notice moved from `skills/muffy/data/ux/LICENSE` to `skills/muffy/THIRD_PARTY_NOTICES.md`, which ships with the skill and names what the notice covers (the `data/ux/` tables, `ux-search.mjs`, the designer's priority model). The ux-search eval checks the notice is there.
- **A gate line's free text answered another gate.** `gateState` read any status line naming the gate, so `gate 2b skipped · the ADR is approved at 3c` counted as 3c skipped. A line recorded for one gate (`gate <id> …`) now answers that gate only.
- **The audit guard never saw a cosmetic fix's severity.** `guard-gates.mjs` loaded only `4b-*.json`, so the rule "a cosmetic fix skips 4b only on a low diagnosis" passed every cosmetic dev spawn; it now loads the 4a hand-off too. `gate-summary.mjs` also reads AC rows in the `AC-<n> | … |` format the Orchestrator writes.
- **Fix and lite checkpoints were read as the feature lane.** `fix-profile.md` and `lite-profile.md` told the Orchestrator to write `fix: skipped …` / `lite: skipped …`, but `laneOf` only matched `fix lane` / `lite lane`. With the guard installed, fix and lite devs (and the lite architect) were blocked on gates 2b and 3c those lanes never ask, the step-4b audit guard never fired, and `check-all` without `--profile` reported false gate errors. The evals passed because they used wording no reference prescribed; they now test the prescribed lines.
- **`check-all` counted `gate 3c not passed` as passed.** Its own regex matched any line naming 3c and the word `passed`; it now uses `gateState`, the reader the gate guard uses.
- **Human gates are enforced, not only written.** Step 2b (`pause:plan-review`) and step 3c (`pause:design-review`) were prose: a run could spawn designer, frontend-dev and backend-dev with no answer on record, and merge after a rejected review. Now:
  - `guard-gates.mjs` (PreToolUse on `Agent|Task`, installed by `--with-guard`) blocks a spawn until its gate is recorded as passed or skipped. Spawns are matched to a task by the `Task:` header of the prompt envelope.
  - `checkpoint.mjs gate <dir> 2b|3c approve|reject|skip` is the only writer of the gate lines in `## Status`. Approval needs the pause saved first and a ready `gate-summary.mjs` body; skipping 3c is refused once `design.md` exists.
  - `check-all` has a `gates` check: a hand-off past an open gate is an error (feature lane only).
  - Rules live in `scripts/gate-rules.mjs`; offline checks in `scripts/lib/gate-evals.mjs`.
- **Known limit:** no hook can tell the user's reply from one the Orchestrator types. The answer is a dated, auditable line in `## Status`.
- **The gate guard fails closed.** A run built spawn prompts by hand, with no `Task:` header, so `guard-gates.mjs` let every spawn through and designer, architect and devops started before gate 2b was recorded. Now:
  - A gated muffy role spawned without the header is matched to the task its prompt names (`.worktrees/feature-<task>` or `.team/<task>`) and checked as usual. It is blocked when the prompt names no task while any checkpoint exists in the repo. Roles outside muffy, and product-manager and researcher, are not affected.
  - `checkpoint.mjs unpause` refuses to clear `pause:plan-review` or `pause:design-review` while the gate has no recorded answer, including after a rejection. `checkpoint.mjs gate` records the answer and clears the pause.

## v1.3.0 — 2026-10-22

Changes since v1.2.0.

### Added

- **Routing:** `/muffy feature` forces the full flow without triage. Only the route decision is skipped; intake, `pause:scope` and every gate still run. New route-sim signal, two scenarios and a README section.
- **Routing:** one decision order, four new routes, and a route eval. Requests are routed to the owning agent.
- **Lite lane** for internal work with a known shape.
- **Presenter agent** for client and end-user decks (`/muffy present`). Present mode now sits with the product-manager; the designer builds the deck.
- **Diagrammer agent** owns drawing, validation, the render check and readability (plain words, sequence) of every diagram. Split out of the designer; facts stay with their owners.
- **Diagram kinds:** state, deployment, gantt and story-map (product-manager). Optional patterns: queue-bottleneck, lifecycle, trust-boundary, delta, db-schema.
- **Diagram import/export:** import Mermaid, draw.io and Excalidraw as a muffy draft (reads gantt and journey); export any kind as PNG or native SVG.
- **Diagram checks:** readability checks, either/or branches in flow, render check at every delivery gate, standalone diagram mode.
- **Platforms and infra:** non-web platforms, providers, infra and stack learning.
- **Brain:** falls back to `.team/brain` when no vault is set; closing can append an optional daily-note link to the vault.
- **Agents:** `display_name` in agent frontmatter (devops is "Cay"); source file size cap for FE/BE agents with a language-neutral split rule.
- **Guards:**
  - `guard-git` blocks subagents from changing git setup.
  - `guard-env` blocks inline interpreter code that loads `.env`.
  - `check-checkpoint` requires `tok:` on every spawn line, and flags a `tok` that drops for the same step and agent.
  - `check-ownership` catches FE/BE conflicts before the step-5 merge.
  - Agents learn their write scope before acting. The `guard-write-scope` rules moved to `scripts/write-scope.mjs`, shared with `make-envelope.mjs`. The envelope refuses a `Write:` path the role may not write.
- **Scripts:** `run-quiet.mjs` (digest instead of full output), `make-envelope.mjs` (validated prompt from flags), `baseline-delta.mjs` (changed folders since the baseline commit).
